# 소유자가 제어하는 에이전트 접근

Claude·ChatGPT는 OAuth로 연결하고, 직접 설정하는 클라이언트는
**설정 → 에이전트 접근**에서 만든 Bearer 토큰으로 연결할 수 있습니다.
두 방식 모두 같은 도구, 접근 기록, 소유자 승인 절차를 사용합니다.

## Claude와 ChatGPT 연결

공개 서버는 HTTPS로 제공하고 `ARO_MCP_ALLOWED_HOSTS`에 정확한 공개 호스트를
등록하세요. 기본 포트가 아니면 포트도 포함하며, 여러 호스트는 쉼표로 구분합니다.
설정 후 앱 컨테이너를 다시 만드세요. 설정이 없으면 localhost만 허용하고,
명시적 목록을 설정하면 그 목록만 허용합니다. 와일드카드는 사용하지 마세요.
TLS를 종료하는 프록시는 공개 `Host` 헤더를 보존해야 합니다. OAuth 주소를
만들 때 전달된 호스트·프로토콜 헤더는 신뢰하지 않습니다. 앱 접근은 신뢰하는
프록시로 제한하고 기존 클라이언트 IP 규칙에 맞춰 `TRUSTED_PROXY_HOPS`를 설정하세요.

1. **claude.ai:** 설정 → 커넥터 → 사용자 지정 커넥터 추가에서
   `https://<host>/api/mcp`를 입력하고 연결하세요.
2. **ChatGPT:** 설정 → 커넥터(화면에 따라 앱) / 개발자 모드에서 MCP 서버를
   추가하고 같은 주소를 입력하세요. 메뉴와 기능 제공 여부는 계정·워크스페이스에
   따라 다릅니다.
3. 아로의 `/oauth/authorize`에서 요청을 확인합니다. 로그인하지 않았다면 로그인 후
   같은 요청으로 돌아와 `/oauth/consent` 승인 화면을 엽니다.
   연결 이름, 돌아갈 호스트, 요청한 권한을 확인하세요.
   이름은 클라이언트가 제공하므로 검증된 신원으로 간주하지 마세요.
4. 요청된 권한 중 읽기와 캡처는 기본으로 선택됩니다. 수정 제안은 직접 선택해야
   합니다. 거절하면 등록된 주소로 `access_denied`와 원래 `state`를 돌려보냅니다.

| 권한 | 도구 | 할 수 있는 일 |
| --- | --- | --- |
| `read` | `search_notes`, `get_note` | 활성 노트 검색과 내용 읽기 |
| `capture` | `capture_inbox` | 인박스에 텍스트 추가. 노트를 직접 만들지 않음 |
| `propose-write` | `propose_note_update` | 명시적으로 허용한 노트의 수정 제안 |

수정 제안의 초기 허용 노트 목록은 비어 있습니다. **설정 → 에이전트 접근 →
OAuth 연결**에서 노트 주소의 UUID를 추가해야 제안할 수 있습니다.
각 수정은 소유자가 별도로 검토하고 승인해야 적용됩니다. 노트 버전이 달라지면
오래된 제안을 적용할 수 없습니다.

## 연결 확인과 회수

OAuth 연결은 토큰이 갱신돼도 연결당 한 줄로 표시됩니다. 클라이언트 이름,
**OAuth** 표시, 권한, 최근 사용 시각을 확인할 수 있습니다.
**접근 회수**는 해당 연결의 모든 접근 토큰과 갱신 토큰을 무효화합니다.
다시 사용하려면 클라이언트에서 새로 연결하고 승인하세요.
접근 기록에는 도구, 결과, 대상 ID, 시각만 남으며 노트 본문이나 토큰은 남기지 않습니다.

## 직접 만든 Bearer 토큰

기존 토큰과 화면은 계속 사용할 수 있습니다. 새 토큰은 기본적으로 읽기 전용이고
만료 시간이 없습니다. 토큰은 한 번만 표시하며 해시와 기존 표시용 접두부만 저장합니다.
의도한 클라이언트의 비공개 설정에 보관하고 노트, 저장소, URL, 터미널 기록이나
공유 대화에는 넣지 마세요.

Streamable HTTP 클라이언트에서 `/api/mcp`와
`Authorization: Bearer …` 헤더를 사용하세요. **연결 설정 복사**는 주소와 헤더
객체를 복사하므로 클라이언트 형식에 맞춰 사용하세요.
MCP 프로토콜 버전은 `2025-06-18`입니다. 허용되지 않은 도구는 목록에서 숨기고
직접 호출해도 거부합니다. 캡처·제안은 작업마다 UUID `requestId`를 만들고,
결과가 불확실할 때만 같은 내용과 ID로 재시도하세요.

## OAuth 동작

- 모든 클라이언트에 S256 PKCE를 요구합니다. 코드는 10분 동안 한 번만 사용할 수
  있고, 접근 토큰은 1시간, 갱신 토큰은 30일 동안 유효합니다.
- 갱신할 때 갱신 토큰을 교체합니다. 사용한 코드나 교체된 갱신 토큰을 재사용하면
  연결 전체를 회수합니다. 갱신 시 권한을 줄일 수 있지만 늘릴 수는 없습니다.
- 토큰은 승인한 `/api/mcp` 주소에 묶입니다. `resource`를 보내면 그 주소와 정확히
  같아야 합니다.
- RFC 7591 등록은 공개 `none`과 비밀키를 쓰는 `client_secret_basic`,
  `client_secret_post`를 지원합니다. 비밀키는 한 번만 돌려주며 토큰 발급 시
  반드시 확인합니다.
- HTTPS Client ID Metadata Document도 지원합니다. 문서의 `client_id`가 요청 URL과
  같아야 합니다. DNS 주소를 고정해 연결하고 사설·루프백·링크 로컬 주소를 거부합니다.
  리디렉션은 따르지 않고, 5초·16 KiB로 제한하며 60초 동안 캐시합니다.
  이 방식은 공개 클라이언트이며 PKCE가 필요합니다.
- 돌아갈 주소는 등록·조회한 값과 정확히 일치해야 합니다. 모든 호스트의 HTTPS와
  localhost·127.0.0.1의 HTTP를 지원하며 ChatGPT·OpenAI 호스트를 하드코딩하지 않습니다.
- 등록은 클라이언트 IP당 시간당 20회, 나머지 OAuth 요청은 분당 120회로 제한합니다.
  코드, 갱신 토큰, 클라이언트 비밀키는 SHA-256 해시만 저장합니다.

주요 경로는 `/.well-known/oauth-protected-resource`,
`/.well-known/oauth-protected-resource/api/mcp`,
`/.well-known/oauth-authorization-server`, `/oauth/register`,
`/oauth/authorize`, `/oauth/consent`, `/oauth/authorize/decision`, `/oauth/token`, `/oauth/revoke`입니다.
검색 문서와 공개 OAuth API는 자격 증명 없는 브라우저 CORS와 OPTIONS를 지원합니다.
승인 POST와 설정 API는 소유자 세션과 동일 출처 검사를 요구합니다.
추가형 마이그레이션은 PostgreSQL `0015_oauth_clients`,
SQLite `0008_oauth_clients`이며 기존 데이터를 바꾸거나 지우지 않습니다.

## 캡처 웹훅

MCP를 사용하지 않는 자동화는 별도로 만든 `capture` 권한 Bearer 토큰으로
`POST /api/webhooks/capture`에 `{requestId, text, title?}` JSON을 보낼 수 있습니다.
성공하면 HTTP 202와 인박스 ID를 돌려줍니다. OAuth 토큰은 `/api/mcp` 전용이므로
이 웹훅에서는 사용할 수 없습니다. 로그인 쿠키도 사용할 수 없습니다.
URL 조회, AI 보강, 외부 웹훅 전송이나 노트 직접 수정은 하지 않습니다.

전체 기계 사용 계약과 경로 표는 [영문 문서](AGENT-ACCESS.md)를 참고하세요.
